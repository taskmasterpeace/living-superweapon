# Reusable fortification kit

Data lives in `src/data/fortification-kit.js`; rendering is an adapter in `src/engine/fortification-kit.js`. The kit is newly authored using the game's existing flat-shaded Three.js material/geometry system. It is not a copied asset or a Highwall-only facade.

The restored facilities catalog was inspected first. It contains equipment printer, aircraft printer, cloning vat, fleet warehouse, runway strip and vehicle printer. Their native catalog dimensions and roles describe complete fabrication/warehouse structures; none supplies detachable wall panels, corners, gates, bunkers, railings or stair modules. The 30m warehouse is a useful existing destination/facility, but forcibly scaling it into a 6m wall would destroy its proportions and sockets. These six assets remain intact. No asset was falsely relabeled as reused. Existing runtime materials, scale contract and collision representation are reused.

## Standard dimensions

One unit is .19m. Primary wall height is 48u / 9.12m (approximately thirty feet). Full panel length is 32u, half length16u, depth12u. Structural columns reach52u. Low cover7u, half-height24u. Gate frame64×52×16u contains a40×44u aperture; the separate closed leaf40×44×8u uses the existing gate controller. Tower32×66×32u has a48u platform. Bunker48×26×40u has a16u entrance, roof26u, interior terminal socket. Stairs16×24×48u and stepped ramp16×24×48u reach the24u platform. Explicit dimension overrides are supported for migration and scale metadata with geometry.

Registry IDs: `tall-wall`, `tall-half-wall`, `tall-corner`, `tall-end-cap`, `tall-pillar`, `tall-gate-frame`, `tall-closed-gate`, `tall-open-gate`, `tall-tower`, `wall-tower-transition`, `low-wall`, `half-height-wall`, `low-corner`, `barricade`, `sandbag-barrier`, `fence`, `bunker`, `ramp`, `stairs`, `raised-platform`, `wall-walkway`, `ground-platform-transition`, `camera-mount`, `searchlight-mount`, `antenna-mount`, `aa-hardpoint`, `terminal-mount`, `gate-interaction-point`.

Placement input: `{id,moduleId,x,y,z,rotation,span?,height?,depth?}`. Rotations are degrees restricted to quarter turns. Ground-centred origin. Full panel atx0 connects half panel atx24, next half atx40. Connections match socket type, world position and opposing normals. The later editor can consume the same registry and placement records. No editor UI is added.

`fortificationPlacement()` returns physical AABBs, contained paint-region descriptors, connections, interactions, device mounts and traversal links. `buildFortificationKit()` emits the exterior surface of the physical box union, trims coincident/interior structural faces, and divides each exterior face into non-overlapping material regions. Armor and accent regions are not separate nearly coplanar meshes. It batches those surfaces by shared material and exposes identical solids plus instances on `group.userData`; it includes a disposal hook. Collision/navigation/projectile/visibility callers must consume these solids, not a bounding box around an entire bunker or gate frame. Interiors and apertures are intentionally represented by multiple solids.

Dimension migration preserves construction constraints: stairs regenerate riser counts instead of scaling them beyond1.5u; the stepped ramp uses.5u. Gate frame posts remain12u and lintel8u at larger spans, so94u span yields70u clear opening. Instance `navigation.openings` reports the actual aperture. Bunker floor stays2u above placement origin even when the roof height changes, and its entry/terminal metadata follows that floor. Tower pieces coplanar with the upper deck explicitly support standing; a decorative fascia cannot become an invisible barrier at the deck edge.

The palette uses pale armor, graphite frame/caps, subdued green structural bases and a narrow muted red identity inset. Bases and caps project beyond the narrower armor shell as actual physical geometry. Pillars, clear gate apertures, hollow lookout decks, firing-slit bunkers, low cover and access steps have different silhouettes.

## Limits requiring integration acceptance

Ramp is honestly **stepped access**, with .5u risers rendered exactly as colliders; no analytic smooth-slope support is claimed. Stairs use at most1.5u risers. Traversal metadata does not itself implement AI navigation. Towers require connecting stairs/walkways to the48u access socket. Hardpoints are structural attachment metadata, not fake AA, camera, sensor or weapon entities. Fence rays hit actual bars, so gaps admit sight/projectiles; navigation must still consider actor clearance. No breakable/destructible state is implemented. Visual lineup and native Highwall navigation/projectile/visibility/gate/vehicle acceptance remain separate from unit tests.

## Source-kit evidence

`node --test tools/fortification-kit.test.mjs` passes 9 focused tests: skin containment, snapping, rotation, gate aperture, access heights, bunker interior/roof, renderer/physics identity, dimension migration and the native tower-fascia/bunker-threshold regressions. `node tools/fortification-kit-browser.mjs` generates `artifacts/fortification-kit/module-lineup.png`, `soldier-wall-scale.png` and `result.json`. This is isolated source inspection, not a substitute for Highwall gameplay. The current visible soldier mesh measures9.1898u (1.746m); the48u wall is5.22times that height. Scale follows the live modular-character formula, without applying the.19conversion twice. Native floor/door/AI/projectile acceptance is reported by the integrating Highwall work.

Native perspective inspection subsequently exposed depth fighting hidden by the orthographic source preview. `tools/fortification-depth-diagnostic.mjs` captured unchanged native near.6/far4200, disabled-shadow, disabled-print and near8 comparisons. Turning off shadows or the print pass did not remove the artifact; increasing the near plane did. The renderer was corrected instead of changing the game camera: only union exterior faces remain, with direct material regions. `artifacts/fortification-kit/depth/exterior-faces/baseline.png` shows the corrected native perspective with original near/far, shadows and print pass enabled. The ninth focused test prevents duplicate exterior triangles and parallel accent layers. Gameplay/navigation data did not change for this correction.
