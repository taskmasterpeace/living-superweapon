## Resource constructs: current ownership and lifecycle

`Game.spawnConstruct` constructs and registers the native object in `game.constructs` (`game.js:3250`). The owning ability holds a second reference in `slot.active` (`abilities.js:485`). A press only reaches `trigger()` after `ready()` checks cooldown, entry affordability, hitstop, stagger and stun (`abilities.js:26`, `abilities.js:483`). Thus a future resource construct cannot assume the existing press path always allows dismissal when energy is low. `holdTrigger` also fires on a release edge (`abilities.js:487`); distinguish action, dismissal and input cancellation deliberately.

The fixed lifetime is `def.duration || 9`; `update()` always decrements it before actions. Native wall detonation and turret dismissal end by setting `life=0` (`summons.js:185`, `summons.js:190`). Existing fist/hammer/turret operations retain their configured behavior during surface assembly. `ConstructSurface` is a presentation layer driven after motion (`summons.js:247`), with appearance defaults/overrides taken from `owner.def.effects.construct` and `def.constructFx` (`summons.js:151`).

The native cleanup is useful: `_dispose()` is idempotent, releases a held victim, removes its wall cover, retires the surface layer, removes the scene object, and disposes unique geometry/material resources (`summons.js:250`). Match starts and round rebuilds explicitly dispose all constructs (`game.js:1846`, `game.js:1973`, `game.js:2035`). The simulation removes a construct from its array only when `update()` returns false (`game.js:3904`). A new immediate-disposal path must make a later `update()` return false without stepping disposed state.

Owner cleanup is incomplete for resource lifetimes. Fighter KO clears all `slot.active` references (`entity.js:1106`), but `clearSlotFx()` does not retire constructs (`abilities.js:98`). Fighter disposal handles rig, slot FX, mines and item meshes, but not the construct array (`entity.js:634`). Construct update has no owner-alive or owner-membership guard. Consequently a timed construct can outlive its owner and the ability loses its reference after KO; character replacement can leave an old owner retained until expiry. Existing KO releases entities grabbed by that owner (`entity.js:1104`), which prevents an indefinitely held victim but does not remove the construct.

This behavior must not be silently rebalanced. Keep an absent lifetime setting on the existing timed branch. Give the newly authored resource policies explicit KO, removal, dismissal and depletion cleanup; document any separately approved change to legacy owner-death behavior.

### Required tests for that slice

- Legacy default and explicit legacy duration retain current expiry, actions, entry costs, cooldowns and cleanup. New data must not alter shipped-kit durations.
- Continuous drain is equivalent across 30/60/120 Hz; zero/partial/large final ticks, multiple same-owner objects, input pause and infinite cores cannot make energy negative or emit repeated depletion feedback.
- Damage-backed mode debits only real damage to the object. Test friendly/enemy filtering, zero/nonfinite inputs, maximum energy loss, multiple hits and simultaneous projectile/blast contact. Owner health, XP, KO count and city destruction counters remain correct.
- Projectile, charged/split projectile, traveling beam, explosion and melee (when included) can contact the resource object using its actual permitted shape. Test occlusion, altitude, moving tank bounds, no future-reach beam damage, and no same-hit double billing.
- Depletion, manual dismissal, owner KO, owner removal/swap, match reset and preview reset remove the scene object, cover/proxy, target registration and `slot.active`; release held victims and dispose owned resources exactly once. A disposed object cannot step or fire later.
- Native tank has bounded formation, movement, turning, targeting, cadence and outgoing projectiles, with owner source attribution. No generic city shatter or humanoid ragdoll assumptions.
- Profile and full-character roundtrips retain lifecycle and tank parameters; old profiles default unchanged; invalid combinations/unknown fields fail; source identity drift drops incompatible overrides. Studio drain/damage/depletion are the production outcome, not visual toggles.
- Run browser acceptance afterward for formation, sustained cost, visible incoming damage, depletion/dismissal, controls and a short concurrent-object soak. Passing Node tests alone is insufficient evidence of readable play.

## Notes on other requested systems

Nanite work can reuse the driven forearm attachment convention and the existing surface-assembly technique, but fitting a custom body, forming a solid cannon/shield and breaking a local part need their own data and runtime. The current firearm emitter searches held weapon children on fists (`weapon-emission.js:3`), so a cannon directly mounted on a forearm needs an explicit socket/attachment lookup; it cannot assume the held-weapon scan finds it. Progressive form rebuilding and weapon unmounting already manage attachment ownership; new nanites must join that lifecycle. Shield ripple appearance alone does not establish protection or damage-disabled equipment.

Military escalation has meaningful existing state: heat decays after a quiet period (`police.js:294`), country/district data affects dispatch, reinforcements are capped (`police.js:374`), and sanctioned fighters target the offender (`police.js:448`). Preserve those hooks when introducing tanks or aircraft. Distinct tracked, fixed-wing and rotorcraft handling, player occupancy, human-zombie conversion, horde budgets and finite-range ballistic spit remain separate designs. The requested valid flight escape is an acceptance criterion for future enemies, not a behavior verified here.

The input mechanism is already specifically defensive against accidental firing. RMB uses a 150 ms selection window, quick taps fire on release, scrolling cancels the old preparation and requires a fresh gesture (`combat-selection.js:15`). Event-time modifier capture survives RMB release before the next frame; direct-key/pad ownership is preserved (`combat-selection.js:42`). A long RMB hold may already have fired before a later scroll; cancellation cannot undo an already committed shot. The current tests establish gesture suppression and release ownership, not a guarantee that an arbitrarily late scroll retroactively cancels prior gameplay.

Correspondent highlights are actual frames from an independent field camera, not re-simulated combat (`newscrew.js:603`). Event hooks include KO, tier changes, big hits, civilian collateral, cars, buildings and police escalation. The recorder uses approximately one second of pre-roll, a 90-frame active-clip cap, up to nine retained clips, a 360-frame/24 MiB budget, asynchronous JPEG admission and shedding (`newscrew.js:24`, `newscrew.js:472`, `newscrew.js:503`). It skips captures under frame-pressure, so missing footage in a throttled/headless tab is not proof the camera does not exist. End-screen playback refreshes pending frames and includes slow-motion windows (`hudBroadcast.js:184`, `hudBroadcast.js:195`). No standalone movie-file export was established by this audit.
