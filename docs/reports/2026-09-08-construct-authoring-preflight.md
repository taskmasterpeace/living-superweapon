## 1. Preserve sparse sources; form filtering is not present yet

- `attack-tuning.js:219` `definitionsFor` currently filters only `existingOnly`/`requires` flags, not construct form. Adding a `construct` registry key alone would make every construct a supported tuning source. Gate resource fields to genuine wall/tank sources and tank fields to genuine tanks; never offer `construct`, `type`, entry `cost`, `cd`, `holdTrigger`, or arbitrary emitter flags as construct overrides. Leave fist/hammer/turret resource authoring unsupported. The existing four attack types' editable cost/cooldown fields must remain unchanged.
- `sourceValue` (`attack-tuning.js:225`) supplies **display/validation defaults**, including truthy-zero fallbacks; `isOverride` (`:239`) strips values equal to those defaults. `applyAttackOverrides` (`:392`) materializes only genuine source plus sparse values and restores previous genuine sources first. Do not replace this with merging the complete `validateValues` result or every displayed field into the attack. An untouched wall must not acquire `constructLifetime`, rates, tank settings, or a default duration. Reset must remove tuning metadata and return the exact source, including absent fields.
- Native `resolveConstructPolicy` (`construct-policy.js:12`) validates both rates even when dormant, rejects unknown modes/forms and rejects resource fist/hammer/turret. It returns zero for the **inactive** rate (`:22`): that result is not authoring storage or a display-default source. Keep valid dormant authored rates through mode switches; validate `{...source,...sparseValues}` without persisting normalized fallback fields. Native tank bounds are `tankSettings` (`construct-tank.js:14`); the authoring metadata must match those bounds, including blast >= 1.
- `attackFields` (`attack-tuning.js:349`) already derives current values from source plus sparse overrides. Its native renderer (`studio-main.js:86–88,114–116`) does not yet interpret inactive/disabled fields. Both rates and duration need visible inactive-mode explanation and disabled controls, not disappearing data. `attackSource`/the identity display (`studio-main.js:105–107`) provide the source-bound identity; add read-only cost/cooldown/form clarity here, not mutable inputs.

Fixtures: extend the patterns at `tools/attack-tuning.test.mjs:90,131,189,203`. Deep-equal untouched AURUM q, ORIGIN `wall`, and ORIGIN `forcewall`; test a wall with absent duration. Set both rates, switch upkeep → damage → timed, apply repeatedly and reset; assert inactive values survive while reset removes every override. Exercise invalid mode, unknown form, unsupported resource fist/hammer/turret, tank-only fields on wall, zero/negative/nonfinite/out-of-bounds rates **including dormant ones**, and forbidden cost/cd/kind patches. The existing registry test at `:51` deliberately expects four types and must be intentionally extended, not mistaken for an unrelated failure.

## 2. Snapshot consistency is not source authorization

`attackIdentity` (`attack-tuning.js:213`) is a stable serialization of the entire source, not an authenticated identifier. `normalizeEntry` (`:279`) checks that the supplied identity matches the supplied snapshot. An importer can recompute both after modifying cost or form. The protection is later reconciliation against `attackSource(def,slot)` (`:340`) and applying the genuine source rather than imported `entry.source` (`:397–402`). Preserve both boundaries.

The actual package path is `validateCharacter` → `importCharacter` → `buildDef(pack.picks,newId)` → `applyProfile` → `applyAttackOverrides` (`character-package.js:20,50–57`; `creator.js:295–298`; `studio-profile.js:131`). Recipes accept catalog power IDs, not raw abilities (`character-package.js:39–40`); top-level package fields reject raw `def`/callbacks (`:21`). `validateCharacter` and `exportCharacter` alone do **not** reconcile snapshots to the chosen recipe. A self-consistent stale/forged snapshot can be structurally accepted but must be stripped on application. The profile-only UI explicitly reconciles against the installed hero (`studio-main.js:353–355`); package import performs it through the rebuilt definition. The current path provides this protection without a new profile/package schema.

Fixtures: extend `tools/attack-tuning.test.mjs:153,219,240` and `tools/character-package.test.mjs:8,24,33`. Use a real new `willtank` catalog pick, author resource settings, export, JSON round-trip, import into an empty roster/new ID, and compare `attackSource` and effective abilities in gameplay and Studio. Forge snapshot cost/form/damage plus a **recomputed** identity; assert the imported runtime retains catalog source and drops the override. Separately change `values.cost`, inject raw top-level `def`, and inject unsafe keys; those should reject before storage. Change a wall recipe to a different wall source (same type, different native cost/cd/source) and ensure stale values do not migrate. A profile changed only in hero presentation must retain compatible values. Do not claim direct editing of existing localStorage records is authenticated by this import boundary.

## 3. Smallest shared regen seam: ordinary regeneration only

There is a demonstrated parity gap: attack `StudioCombat.step` manually advances slot cooldowns and pose (`studio-combat.js:195–196,261–266`), never Fighter regeneration. Native `Fighter.update` regenerates before Game's upkeep (`entity.js:1471–1480`; `game.js:3918–3934`). Copying `8 * dt` into Studio would omit native preparation, sheet, mood, wounds and clamping. Calling full `Fighter.update` would introduce physics, status clocks and movement into the anchored rehearsal.

Recommended narrowly authorized extraction: a `Fighter.regenerateKi(dt, anyCharge = Object.values(this.slots).some(s => s.charging || s.sustainT > 0))` method containing only the existing two-branch calculation at `entity.js:1479–1480`. Native `update` calls it at the same location with its already-computed `anyCharge`; preserve the exact arithmetic and native zero-dt behavior. Leave charge-yell clocks (`:1474–1478`), guard/safe-charge extra regeneration (`:1486–1512`) and all movement/status code where they are. This new helper is an ordinary-regen seam, not a replacement for the whole Fighter update.

In Studio, enable that call only when Attack mode's **selected primary or selected secondary definition** is a valid resource wall/tank, not merely when a live construct exists. Run it once per positive simulation tick, after both `runSlot` calls and before grouped upkeep/projectiles/constructs. This makes pre-spawn and post-dismiss time consistent while preserving timed-only and other existing previews' no-regen behavior. Do not regen the measurement target. Stage fixtures have no guard-stance input; do not claim this seam newly rehearses guard/power-charge energy. Existing melee mode already uses full Fighter updates (`studio-melee.js:55–57`); adding another helper there would double-regen.

Subtleties to preserve:

- Entry/charge payments happen before this regen tick; same-frame later regen must not retroactively allow a denied press. Determine `anyCharge` after **both** slot inputs. Use the exact `charging || sustainT > 0` predicate, not `state === 'charge'`, active beam existence, `pendingLaunch`, construct assembly, or a displayed phase. On the native charge-release tick, `st.charging` clears before regeneration (`abilities.js:265–270`).
- Infinite cores pin ki to `maxKi` in that ordinary calculation; `spendKi` and construct debit alone do not pin it (`entity.js:1126`; `construct-policy.js:24–33`). Do not emulate infinity with an infinite number or serialize `Infinity`. A preview starting-energy control is encounter state, not a source/profile mutation; reset can explicitly start infinite owners at max and display the native infinite status.
- Finite regen clamps to `[0,maxKi]`, including near-max pools, before upkeep. Netting upkeep and regen into one expression changes cap behavior and exhaustion. Preserve `sheet.kiRegenMult`, `moodMult(...,'kiRegen',1)` and torso wound attenuation exactly; native mood lookup is `psyche.js:170`.
- Native KO (`entity.js:1465`) and the frozen branch (`:1399`) skip regeneration. A resource-only stage call must respect those gates if such fixtures are used. Hitstop is **after** regeneration (`:1516`), so do not gate ordinary regen on hitstop/general ability readiness. Full freeze/status simulation remains native test coverage rather than an invented Studio status engine.

Focused fixtures for the extraction: extend the native Game boundary fixture `tools/construct-policy.test.mjs:193` (currently asserts 1 ki + 8/s regen - 10/s upkeep over .05s = .9 ki and .5 spent). Add shared-helper/native and resource-stage cases for charging vs release ticks, a charged secondary slot, `sustainT > 0`, finite near-max clamp, zero regen multiplier, deterministic mood multiplier plus torso wound, and infinite-core pin/debit. Verify a hitstopped owner still regenerates, a KO/frozen owner does not, and existing non-resource low-ki Studio audio fixtures (`tools/studio-audio.test.mjs:49`) and timed construct fixtures retain their outcomes. Control regen to zero in pure hit-amount equality tests, rather than mistaking net pool change for received damage.
