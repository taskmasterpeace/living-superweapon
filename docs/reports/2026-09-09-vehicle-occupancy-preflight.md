## Bottom line

Keep the Fighter as the human identity and delegate its controls to a separate vehicle actor. Neither existing possession nor the cosmetic mount supplies safe occupancy. Safe exit requires a swept *whole-body* route through a real access corridor, a current free destination, and actual support—not just a nearby point or LOS ray. “No exterior candidate” is not permission to damage, kill, fly, teleport or hide the occupant indefinitely.

The smallest promising emergency design is a continuously world-clear, body-sized **release volume** carried by the seat, with a separately approved destruction treatment for the vehicle's own geometry. A historical position alone cannot provide that guarantee. No native military model/actor exists yet, so local hatch dimensions, a crash-safe release volume, and a complete destruction policy cannot be truthfully marked geometry-tested today. Tasks 5–7 need the exact fixtures below after Tasks 1–4 supply the actual actors; the controllable-vehicle requirement remains required, not quietly replaced by AI vehicles.

## Proposed ownership and control boundary

One manager-owned seat transaction links an existing Fighter to an existing vehicle. Add no saved profile field, alternate hero, hidden immortal crew Fighter or mutation of `def`, abilities, flight tier, team, speed, source ID, energy or health.

Suggested additions to the existing brief's `vehicle-controls.js` interface:

```js
vehicleFocusFor(game, fighter); // current eligible access descriptor or null; no P1-global focus
tryEnterVehicle(game, fighter, vehicle); // existing {ok, reason}; all checks before side effects
tryExitVehicle(game, fighter, {emergency:false}); // existing {ok, reason}; never forced damage
clearVehicleInput(game, fighter, reason); // tells/held state only; not a seat release
releaseVehicleOccupant(game, fighter, reason, checkedRelease); // manager-internal commit
// checkedRelease is a fresh query result, not caller-supplied arbitrary coordinates.
```

`fighter._vehicleSeat = {vehicleId, seatEpoch}` and `vehicle.occupant = fighter` are reciprocal runtime links; VehicleSystem owns an incrementing seat epoch for entry/release/reset and validates both links before every submitted intent/fire. `controller:{kind:'fighter',fighter}` identifies the pilot, not the vehicle's attack source. Reserve/commit at a positive-time controller boundary, stable human/controller ID order, before `beginContactFrame`. Two claimants for the same seat produce one success; no half-applied hidden actor. Clear the consumed interact gesture and return immediately—do not continue hero input on the entry frame. An exit frame likewise does not then fire/strike as the hero.

Initial proposed entry legality: live local Fighter and live vacant vehicle, not paused/match-over/network; vehicle physically supported and all access-point speeds <= the brief's proposed 2u/s; validated access distance/height (the brief's 3u vertical band), current LOS plus full swept body route. Refuse `grabbedBy`, `grabbing`, `grabState`, `_carry`, active/recovering strike, stagger/stun/frozen/downed/sleep, hanging/grapple, `_mount`, possession on either side, `_inert`, banishment, active wall/TK/elastic transform ownership or a body that cannot fit. This is a closed incompatible-state gate, not `noPowers`. Retain equipped gear/items; pending attack preparations may be cancelled on a successful entry only. A denied attempt does not charge, cancel a paid attack or drop equipment.

Use the brief's proposed context bindings, read through `keymap(SETTINGS.scheme)` and named pad actions. Store a separate mounted-tool record with `slots:{lmb,rmb}`, selections and `_mouseCombat`; pass `mouseMelee:false` to the existing pure sampler. Both triggers selecting one weapon share the same magazine/tell/cooldown owner. Pad vehicle axes are raw normalized commands, not `controlPad`'s nearest-foe steering. No auto-aim is smuggled in. Bot pilots and response AI submit this identical normalized intent to the existing proposed executor; all vacancy/status/LOS/ammo/rate/kinematic checks apply to both.

On entry, successful exit, blur, pause/menu, pad disconnect/reconnect and controller reassignment: cancel only uncommitted mounted tells and hero preparations through their proper owners; stop their loops; reset deferred tap/releases and evade double-tap history for the affected controller. Require neutral then fresh input for triggers, interaction, melee/item/fly/up/down, and movement axes. A physical held pad button on reconnect is not a new command. Do not clear P1 global keyboard/mouse because P2 exits; use a per-controller suppression record. `boot.js:365 clearCombatInput` must call the new mounted cancellation hook while preserving existing hero cleanup. Pause cancels intent, not occupancy, crash state or ammunition. Already fired ordnance survives ordinary entry/exit/focus changes.

### Simulation and presentation order

1. Sync existing seat anchors from the current accepted vehicle pose before controls/status reads. Keep `f.pos` aliased; keep `f.vel` as the hero's own motion/received impulse, normally zero seated, and store vehicle seat velocity separately. Do not replay or freeze status time.
2. Submit intent once; snapshot previous vehicle and melee poses once. Run the existing Fighter update loop once. An occupied `_physics` branch skips independent gait/flight/cover movement; controller gates prevent hero slots/melee/items. Status, actual DoTs, cooldowns and ordinary regen retain native order. Guard is off, so seated “brake” never earns guard regen. Full-update side systems that write transforms or emit active attacks require explicit entry exclusion or scoped occupied handling, not an early return around all status code.
3. Apply vehicle motion and publish current receivers **before** `resolveBodies` and `melee.endContactFrame`, as already accepted. Validate the protected seat/release envelope with each vehicle substep. Sync the still-seated Fighter root once to the final accepted pose, also after frozen/hitstop branches. Exclude it from body resolution and attack target snapshots. Keep the manager's last valid state from the accepted step, not an untested desired pose.
4. Preserve native incoming hits then vehicle fire ordering. A DoT KO, removal, seat epoch change or destroyed actor invalidates queued fire immediately. Do not permit one last shot because the tell was ready before status/contact damage. Do not advance Fighter physics a second time on release. The next ordinary update owns gravity/locomotion.
5. Apply occupied visibility after both fog/no-fog decisions; do not borrow `_inert` or `phase`. Suppress the hidden hero's shadow, target marker and projectile body independently of allegiance. Camera/reticle/listener use the actual controlled actor. On release restore native visibility policy, not unconditionally `visible=true` for an invisible/banished actor.

Keep harmful existing DoTs running. Passive healing, buffs, resource constructs/minions and committed remote attacks do not disappear merely because the caster boards. Conversely, do not claim every timed aura, size/banishment/possession interaction is automatically safe: native `Fighter.update` contains those effects. First occupancy eligibility excludes conflicting active transform/possession states; tests must demonstrate ordinary supported kits retain their timers and that no new hero action originates inside a closed cabin. Cabin protection from *new* area/status effects is a creator decision below, not a global `takeDamage` immunity or a `dot:true` shortcut (beams also use that flag).

## Deterministic whole-body exit query

Proposed new `src/engine/vehicle-exit.js`, created only with the future occupancy gate. It owns geometry queries, not controls, damage or general pathfinding. Keep the actor model's access metadata private in `vehicles.js` model factories until it is real: authored `seatLocal`, protected release bounds, and a fixed ordered list of actual access routes (`id`, cabin-inner point, aperture, exterior point, clear corridor). Do not add unimplemented fields to the public closed vehicle catalog. A tank roof hatch, helicopter side opening and jet canopy are different physical routes; a point on each compass direction is not evidence of an opening.

```js
occupantEnvelope(fighter); // cached upright body offsets {min:{x,y,z},max:{x,y,z},key}
queryVehicleExit(game, fighter, vehicle, {mode:'voluntary'|'emergency'});
// {ok:true, vehicleId, seatEpoch, accessId, root, velocity, support, route}
// or {ok:false, reason, blockedBy}; result is copied, transient and immediately revalidated.
// support: null in clear air, otherwise {kind:'terrain'|'cover'|'interiorRoof',ref,y}
validateReleaseEnvelope(game, fighter, vehicle, pose); // world/dynamic clearance, no mutation
```

These are proposed names/signatures for a small native helper, not APIs that exist today. Query failure cannot mutate position, velocity, HP, flight, geometry or seat links. Stable access ordering, stable obstacle IDs and stable controller order make ties deterministic. There is no random nearby-point search, wall-clock retry, nearest-spawn fallback or distant navmesh relocation.

### 1. Bound the real occupant

Use a conservative upright body envelope containing both the native body prism (`f.radius`, native 11u interior-clearance height) and the supported rig's actual neutral anatomical solid extents at its real frame/size scale. Include settled body attachments that must physically fit; exclude particles, cape trail, aura, selection/guard rings and world-owned effects. Do not use the currently hidden/leaning whole-scene Box3 or assume every custom body is 2.2 by 11. Cache by rig/form and size identity, compute without advancing animation, and measure procedural/male/female plus large bodies. A conservative box may refuse a narrow opening; it cannot shrink until a test passes.

For a temporary smaller/larger body, reserve the union with its native timed restoration envelope. This prevents size expiry trapping a larger hero. Voluntary source/form changes must revalidate the proposed envelope before replacement. Oversize bodies are honestly refused this opaque-seat first slice; no HP-scaled shrinking to fit. Epsilon proposal: 0.02u numerical clearance, independent of hero strength. It is not a step-height allowance, a damage radius or collision forgiveness.

### 2. Query support separately from clearance

- Candidate foot support is the actual terrain heightfield or a live native standable cover/interior roof below the exit route. Terrain samples use `World.heightAt` and `_ghArena`. Enumerate extrema over the square footprint using cell/footprint intersections; bilinear patch extrema occur at rectangle corners. Reject discontinuity/slope outside the approved dismount tolerance. The brief's vehicle 2u step / 0.3rad slope are not automatically hero dismount rules; initial recommended dismount is a clear downward route onto support, not a free step up.
- A standable roof must contain the full footprint with margin and be reached from above, not merely be the highest `top` within `+1.5` radius (`_roofUnder` is intentionally permissive for a hover deck). No snap onto a neighboring roof behind a parapet. Interior ceiling/roof occupancy must be tested explicitly; the walls-only projectile helper does not model it. Reject an unsupported overhang/edge rather than label `onBlock=true`.
- Normal exit requires supported vehicle and destination, low full 3D seat/access-point speed, and acceptable vertical displacement through the authored route. Rotorcraft additionally requires genuine landing-gear support, low descent/drift, and rotor clearance/spool-safe exit. Fixed-wing requires actual stopped supported gear; the air-start drill has no demonstrated runway/landing, so it advertises no normal airborne exit. Voluntary blocked/fast/airborne exit retains control and occupancy with a precise message, never auto-brakes, lands or stalls the aircraft on behalf of the user.
- Reject water as the initial supported entry/normal-exit surface unless an actual approved water exit is tested. Existing `waterAt` is a land/shallow/deep classification, not a buoyancy/rescue system. Emergency clear-air release may subsequently fall into native water; no parachute or free flight is granted.

### 3. Sweep every route segment, not just endpoints

For the upright translating envelope `E=[emin,emax]`, a point/root segment intersects a static box `B` exactly when it intersects the Minkowski-expanded bounds `[B.min - emax, B.max - emin]`. Use the native slab math with explicit vertical-bound contracts, not camera-specific flags. At voluntary final support, allow touching only the selected supporting surface from above; other starting overlap or penetration is a failure. Include all live native `world.cover` regardless of `noCam`/visual fade, native interior walls **and roof/ceiling**, actual arena bounds, and other vehicle current solids/rotor envelopes. Legacy cover's body semantics are conservative downward columns; do not infer bottom from `y0` (it is a center). Newly finite vehicle proxies remain finite and separate.

Against oriented vehicles use the actor's actual solid primitives plus orientation: conservative swept AABB broad phase, then box/OBB or capsule narrow phase. For a translating world-aligned occupant box versus a fixed OBB, continuous separating-axis intervals over the usual box axes and cross axes give entry/exit times. Do not only inverse-transform a center ray and pretend axis padding remains spherical. Against Fighters, check full vertical overlap plus sum of body clearances, not `resolveBodies`' coarse 7u difference or its `d > .001` hole. Do not “resolve” a candidate by shoving another player.

Terrain route clearance can reuse `traceCameraGround` with feet offset (`root.y + footprintHalfWidth` as the queried center for a symmetric footprint), plus the envelope's real minimum-Y offset. Use it only for the ground footprint. Exact support equality is handled explicitly at the final endpoint; do not relax the entire sweep. Include world cell crossings: a thin ridge between clear endpoint/center samples must block. Non-square envelopes may conservatively use the larger horizontal half-extent; report conservative refusals.

Own vehicle geometry is ignored only inside the declared cabin/access corridor of the chosen opening, where the model's real collision decomposition leaves room. Every other own-hull, gun, wing, tail and spinning-rotor part remains solid/unsafe. A center-to-right endpoint that crosses the solid hull is not a valid left-hatch exit. Query both the route and final destination again immediately before commit; the world currently has no authoritative geometry revision counter that makes yesterday's result safe. Moving obstacles use previous/current transforms from the accepted vehicle contact frame; other occupants' committed exits reserve their volume for the remainder of that frame.

Candidate order recommendation: the actual nearby access used to board, then the remaining authored access IDs in fixed order; each access offers its own short outward/downward route. No arbitrary far-side point is generated. Direct assignment to the checked endpoint is a bounded seat transition without a seated-animation claim, not permission to cross walls. If moving traversal/door animation is later added, every intermediate pose must follow the same checked route.

### 4. Release motion and native physics

On a successful exit preserve the existing Fighter/root, restore its native input context, and assign the current seat-point velocity `v + omega × rotatedSeatOffset` within the vehicle's accepted kinematic limits. Do not add a launch impulse, reset actual incoming-hit credit, add invulnerability or set `launchT`/`burstT` merely to preserve speed. Set fly/up/down/cruise/glide inputs neutral; do not restore a stale flight toggle from before entry. Native flight remains available through the next fresh valid hero input. Update native support/air transition history so coyote/settle is not inherited from the boarding location.

Important limit: `Fighter.move` applies native speed caps (`entity.js:2109` onward), so copying an aircraft's velocity does **not** prove sustained ejection momentum. The initial recommendation is to preserve native subsequent motion rather than fabricate `launchT` (which changes slam damage). Record actual first/second-frame velocities in the airborne fixture. If that produces unacceptable instant braking, a narrowly defined egress-momentum rule needs separate parent approval and its own physics tests; it cannot be hidden in collision recovery.

## Destruction with no safe exterior candidate

Three approaches, with explicit trade-offs:

1. **Recommended for evaluation: protected release volume + in-place release after actual own-hull clearance.** While occupied, the actor carries a world-clear envelope large enough for the restored upright Fighter. Motion may be conservatively blocked by this envelope as well as by the chassis. At destruction/occupant KO, first stop weapons and resolve an ordinary checked emergency route. If exterior routes fail but the current release envelope is clear, the vehicle must visibly break/open/remove its own obstructing geometry before a same-place hero release. World walls, other vehicles and terrain stay unchanged. This can yield a visible, controllable hero without teleportation, but the exact breakup/wreck design and timing are a **creator/parent decision** because they alter occupied destruction presentation and possibly collision. It is not approved by this preflight.
2. **Retain a visible exposed occupant in a disabled crash until a route clears.** Can preserve the aircraft's intact descent, but requires an actual exposed seat, attack/control policy and collision-safe release on impact. Without a bounded physical outcome it becomes a stranded actor; not an acceptable default by itself. A timer that expires into forced KO or an invisible release is rejected.
3. **Recall to last-safe position / arbitrary damage / automatic flight.** Rejected. A remembered point may now be occupied or separated by a new wall, and changing HP or flight cannot repair geometry. No fixed 20% max-HP penalty, forced KO, height snap or free parachute.

The protected envelope is a *current* geometric invariant, not an immortal safe bubble. Validate its full sweep before accepting each vehicle motion/rotation substep, including wreck descent if the occupant is still aboard. Store `lastAcceptedPose` and release-envelope data only after validation. Never advance into an invalid pose then rewind several frames through a wall. If the next desired motion is blocked, stop at the swept time of contact under vehicle physics; last-accepted history is a diagnostic/short-step rollback origin, not a destination for future ejection.

**Own wreck is the decisive choice.** At HP zero the accepted aircraft design disables weapons and continues a physical crash; it does not instantly erase the hull. Therefore “just ignore own hull” would let the hero fall through a still visibly solid aircraft, and “delete entire aircraft to eject” would contradict Tasks 3/4's crash gate. Before lifting occupancy holds, choose and test a real occupied variant: for example, the cabin region physically breaks away/open so the release envelope and its downward/outward route are free while remaining wreck pieces still perform the native crash. If the actual model cannot supply that without a broader wreck simulation, return that measured constraint for a decision; do not claim the fallback is complete.

**New obstacles can invalidate even a stopped seat.** Existing `Game.raiseSpike` (`game.js:1033`) and `systems2.js:226 reshape` insert cover, and native construct placement can create geometry; external scripts can also mutate world arrays. Occupancy cannot guarantee safe release merely by checking vehicle movement. A supported live gate needs placement owners to query a read-only occupied-release reservation before adding intersecting solid geometry, or another explicitly approved collision result. This would require narrowly authorized additional placement seams—not silently changing constructs, spikes or map design. Other Fighters/vehicles must not be pushed into this volume by later body resolution. An unsupported external mutation that already encloses the actor is a reported invariant violation: do not pretend a universal non-teleporting solver exists. Such a fixture fails the gate; a hidden held seat is not “passing cleanup.”

**Native damage remains native.** Select a unique explosion event and apply its ordinary typed damage/falloff/knockback/resistance once to an eligible exposed/released occupant, using the same native `takeDamage` pipeline. Do not clone both a cabin damage event and the area's Fighter damage event. Existing invulnerability/phase/resistance/second-wind remain effective; no `trueDamage`, `unblockable` or `_ko` override for geometry failure. Native `areaDamage` is team-filtered and center-distance-based, not cabin-aware; deciding whether an opaque cabin shields new splash, and whether the vehicle's own destructive blast harms its occupant regardless of team, is an explicit damage-policy decision. It is not fixed merely by tagging an event. Preserve existing untagged explosions exactly.

## Identity, targeting and legal credit

- Keep `game.player` / `humans[].fighter` / Fighter ID stable. Pilot is the current seat controller; owner/caster of existing powers remains the Fighter who created them. Military controller tokens are not targetable soldiers. Ordinary mind-control/possession cannot silently seize a vehicle seat or transfer legal identity in this first slice.
- A vehicle shot uses the brief's fresh immutable `vehicleAttackSource`: vehicle ID plus captured pilot credit, team/fixation, source origin and fixed vehicle power. It never reads the *current* pilot on impact. Exiting, pilot KO, hero swap, a later driver or controller-faction change must not transfer an old shell's damage, XP, heat or crime to that later actor.
- `fighterCredit` resolves genuine Fighter responsibility at native `onHit`/KO/police hooks. Preserve physical `src.pos` for direction and source label. `PoliceSystem.onCivHarm` keys the actual Fighter and district at the harm location (`police.js:186`), while `handleKO` currently assumes its killer has Fighter score/XP fields (`game.js:2514`, `:2555`). Never book an AI vehicle-source descriptor as a ghost wanted actor or run Fighter progression on it. A removed original Fighter reference may still identify a committed shot; no ID lookup that redirects to a new incarnation.
- Boarded offender remains the police offender. Relation/fixation resolves the controlled vehicle as the physical target, while the hidden occupant is not separately hittable. Separate “hostile relation” from “targetable Fighter” rather than returning false from all relation checks for the seated offender. Explicitly retain friendly-fire/neutral-collateral policies and do not report hardware destruction as `onCopDown`.
- **Additional credit decision:** a wreck explosion caused by a hostile disabling hit should retain that causal hit's captured responsibility; a pilot-commanded collision would use the recorded responsible pilot rather than the pilot who later boards the wreck. This causal selection and any age cutoff need parent approval; do not invent an officer/civilian crime while assigning fallback ejection. Reset/teardown produces no damage, heat, XP or explosion.
