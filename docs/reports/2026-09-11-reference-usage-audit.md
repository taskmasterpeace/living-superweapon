# Reference-library usage audit — 11 September 2026

## Answer in one sentence

The references were not all ignored: anyCreature and CMU became real, reproducible authoring packages; the three Cortiz examples informed original WebGL effects; img2threejs was recorded only as an authoring **method**; and LinearAbiltyCastingThreeJS had no prior integration. This pass inspected Linear and produced a bounded visual proposal, but did not port its shaders. Most of the authoring work is still optional Studio/viewer infrastructure rather than default roster gameplay, which is why it can look as though the libraries were never used.

## What Linear can save now

Linear's highest-value parts fit the existing engine without replacing the non-negotiable traveling hose:

- **Charge/source:** its beam holds the traveling front at the hand, emits small independent inward batches from a shrinking shell, and shades the source orb with animated displacement, hard surface filaments and Fresnel. The current engine already owns charge timing and has `ChargeGather` plus `createBeamSourceMaterial`; adapting only the visual uniforms/intake pattern there is a bounded **0.5–1 day** improvement. See upstream [`_intakeFx`](https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS/blob/main/src/abilities/BeamAbility.js#L3010-L3092) and [orb shader](https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS/blob/main/src/materials/BeamMaterial.js#L2013-L2091).
- **Readable volume:** upstream draws one parametric tube as axis-weighted core, rim-weighted sheath and wider halo. Local `beam-surface.js` already computes cross-section facing and separates core/glow, so the time-saving move is to borrow the weighting model and shared state—not its flat-floor ability class. A focused three-layer A/B pass plus close/rear-camera regression is **1–2 days**. See [the upstream pass weighting](https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS/blob/main/src/materials/BeamMaterial.js#L2105-L2148).
- **Backwash:** upstream rate-throttles sparks backward/upward from the sustained impact, plus pressure shells and ground rings. Local code already emits accepted-contact rebound fans/rings every 0.18 seconds via `vfx.contact(...pressure:true)`. The useful delta is a persistent, rate-limited wash owned by the reached hose endpoint, stopped on loss of contact; that is roughly **0.5–1 day**, with no damage or collision changes. See upstream [`_burnFx`](https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS/blob/main/src/abilities/BeamAbility.js#L3428-L3569).

Do not import Linear's whole ability manager, flat-ground targeting, particles, post stack or app shell. Those duplicate mature owners here and would cost more than they save.

## Fastest next actions

1. **Make one existing pilot visibly real before adding another library:** assign `equipment.carbine@1` through the SARGE profile and call the already-built equipment loader at fighter/form/respawn boundaries. Keep its procedural fallback until the package loads. This is the shortest path from catalog proof to player-visible integration; the support-hand acceptance blocker still governs final approval.
2. **Turn CMU from “package exists” into “motion used”:** add explicit source-id-to-runtime-role/clip mapping and pilot 2–3 named combat takes with contact/recovery metadata. Do not expand the dataset first. The current Subject 02 package can become a smoke-test override by mapping `cmu-walk → walk`, but it cannot supply jog/sprint.
3. **Delay anyCreature gameplay until a creature is actually on the near-term roster:** the expensive missing work is actor/AI/contact integration, not asset generation. The adapter has already saved that generation work.
4. **Run the bounded Linear source/backwash A/B pass above:** it reuses the current tube, light pool, particle pool, charge authority and endpoint contact, so it offers more visual return than a framework port.
5. **Improve provenance wording:** call the current img2threejs outputs “img2threejs-style procedural factories” unless there is retained evidence that the tool generated them. The revision label proves a referenced method, not generator execution.

One provenance issue matters only if future work copies source verbatim: the three Cortiz repositories describe themselves as free/open-source but currently expose no root `LICENSE` file in their GitHub trees. The existing original implementations do not depend on that ambiguity. Obtain an explicit license before copying substantial shader/source code; continuing to use visual/mechanical ideas and writing project-native code is unaffected. Linear has an explicit [MIT license](https://github.com/achrefelouafi/LinearAbiltyCastingThreeJS/blob/main/LICENSE).
