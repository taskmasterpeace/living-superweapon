## 1. Existing cell API: immutable identity, not hull instance index

`nanite-forearms.js:175 snapshotNaniteCells` returns `{slot,epoch,cell,matrix}` for intact, deployed, unlocked, fully assembled cells, using `view.root.matrixWorld × layout.matrix`. It refreshes matrices, rejects disposed/KO/form-disposed state and mismatched view epoch. Use its unit-box envelope `[-.5,.5]³`; visual `hull` instance indices compact when a cell breaks and are **not** structural cell IDs. Cuff, saddle, vents and traveling fragments are deliberately not cell armor. `nanite-pose.js:13,25–29` already uses these literal cell boxes and cached driver-local `parts.naniteBodyVolumes` for fitted-body clearance.

`nanite-state.js:43 damageNanite` verifies finite positive amount, active assembly/deployment, epoch, intact cell and finite point/normal. It always debits a valid struck cell; shield absorption additionally requires `canAbsorb`. Cannon `remaining` stays unchanged and `disabledSlot` is returned only on break. It does **not** verify geometry, owning target, current source identity or guard legality. Those are caller duties; a bare `contactPoint` must never authorize armor. A forged/stale token must not become valid merely because a similarly numbered slot exists.

Break does **not** change epoch. Repair at completion makes a cell intact again. Source retirement/new life changes epoch; cosmetic form rebuild preserves the state epoch. Therefore:

- Validate current cell/deployment/assembly and live view/source at query and consumption, not epoch alone.
- Clear reusable `out.naniteContact` on every miss/body winner/world winner. Copy its point/normal when retaining an event; do not retain shared temp vectors or a query scratch object that the next candidate overwrites.
- Previous-cell matrices need a same-view/rig identity check as well as `{slot,epoch,cell}`. A form can replace the view while preserving epoch. Do not sweep between unrelated old/new mesh layouts or repair by rebuilding.
