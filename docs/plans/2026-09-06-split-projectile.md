# Authorable remote split projectile

## Behavior and scope

The recovered BFP guide describes a special missile whose remote detonation creates four homing
children. Add that capability as an explicit authoring option for the existing single projectile and
charged projectile types. Do not change the shipped catalog, turn ordinary impacts into splits, add
maps, or permit recursive splitting.

## Production contract

- `splitCount`: zero disables; authored integer 2–8 enables remote splitting. Four is the BFP-style
  setup, but this engine remains a custom-character tool. This is not an original asset/config import.
- Second press splits at the parent's actual current world position and travel orientation, with a
  symmetric cone of children. Use a stable perpendicular basis for horizontal, vertical and stationary
  travel. No random placement and no teleport to aim/target.
- Children are ordinary production homing energy projectiles with the parent's current caster/team,
  palette, damage type and charge-scaled payload. Total direct damage is divided among children;
  child radius/blast scale down. Explicit authoring controls set cone spread, child speed and homing.
- The parent retires once, returns resources, produces a small separation cue rather than a full
  damage burst, and cannot split twice. Children cannot themselves split or be remotely detonated by
  the old parent's slot. Natural parent contact retains its ordinary impact behavior.
- Existing remote intent, ownership/deflection, interruption and AI logic remains authoritative.
  AI may use the same second press; no direct hidden-target selection added.
- Studio controls/package validation use the existing sparse identity-bound metadata. The production
  preview must describe a split rather than falsely labeling it a single burst; verify visible child
  travel and actual subsequent damage, including custom export/import and clean runtime launch.

## Verification order

1. RED runtime tests for count, current position/owner, vertical basis, no recursive split or parent
   explosion, idempotent cleanup, natural impact unaffected, and real child travel/homing.
2. Runtime implementation and schema tests (integer/range, opt-in, unchanged catalog defaults,
   package round trip, charge payload scaling).
3. Studio integration with production preview and truthful telemetry; focused browser RED/GREEN.
4. Independent runtime and visual review, serial real-input/preview regressions and production build.

Root owns runtime/data/tests; Studio worker owns only the existing Studio preview/inspector/test files.
No concurrent production edits during browser validation.

## Lifetime test finding

Initial spawn/ownership/schema review passed, but real Studio contact testing caught an additional
runtime defect: ordinary central-force homing retains sideways momentum after the split cone. Root
reproduced default children orbiting a stationary foe40u ahead until their four-second expiry at
30/60/120Hz. Merely showing four moving objects is insufficient.

Correct guided children with explicit heading response and near-target terminal guidance inside the
same production Projectile class. Preserve legacy ordinary projectile guidance. Bound per-step travel
for guided children so authored high speed does not jump over contact. Validate actual convergence,
zero-homing opt-out, both vertical directions, frame-rate behavior and existing collision/cleanup.

## Swept collision and current verification

The initial 2u movement bound prevented body tunneling but review reproduced tiny, fast children
skipping a one-unit wall. Guided children now sweep the existing cover-cylinder and interior-box
collision shapes (plus ground) before moving. The earliest contact wins; airborne wall explosions
stay at that contact's height. Ordinary projectile behavior remains unchanged.

- All four children directly hit a stationary target before expiry at 30/60/120Hz, at both90 and2000u/s.
- Zero child homing preserves direction. Vertical/stationary split basis remains finite and symmetric.
- Thin interior/cover tests fail before the swept correction and pass afterward; pure geometry tests
  cover reversed travel, height clearance, vertical descent, ground opt-out and starts inside geometry.
- Independent final scoped runtime review PASS, fresh62/62 combined checks. Studio final browser
  passed travel/contact/package/mobile and zero page/console errors. Finish-review telemetry findings
  were corrected and visually rechecked by the controller; this is not overall game readiness.
