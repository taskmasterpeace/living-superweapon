# ATLAS v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline — Robert
> pre-authorized end-to-end execution this session). Steps use checkbox (`- [ ]`) syntax.
> Spec: `docs/superpowers/specs/2026-07-24-atlas-v1-design.md`. Read HANDOFF.md + CLAUDE.md first.
> No test framework exists in this repo; verification is HEADLESS BROWSER assertions per
> HANDOFF.md ("How to verify anything") — every task states its exact console recipe and the
> expected output. That is this repo's TDD equivalent: write the assertion, watch it fail or
> measure the baseline, implement, watch it pass, commit with docs in the same commit.

**Goal:** The map maker becomes ATLAS — a standalone city-generation tool page with doors,
a metric contract, enforced altitude layers, real water depth with living water, Vietnam-grade
forests with canopy cutaway, a funfair, a climate data layer, and residential interiors with
corner warfare.

**Architecture:** Extract the atlas UI out of hud.js into `engine/atlasUI.js` with two mounts
(standalone `atlas.html`, in-game screen). All new authoring controls land in the extracted
module. The planner (`data/cityplan.js`) stays zero-Three.js. New data joins follow the
`geography.js` authored pattern.

**Tech stack:** Three.js + vite (two rollup inputs), vanilla JS, localStorage persistence,
headless verification via the dev-server console (`window.LSW`).

**Perf budgets (from the spec, checked at task 9):** sweep 0 problems · 9×9 combat soak
≤3.5 ms sim · rebuild ≤12 ms · canopy cutaway ≤0.15 ms · no per-frame allocs in new hot loops.
